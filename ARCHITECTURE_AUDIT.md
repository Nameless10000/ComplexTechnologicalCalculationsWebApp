# Фактическая архитектура и план изменений (03.10.2026)

- Основной solution: `ComplexTechnologicalCalculationsWebApp.sln`, .NET 8, xUnit.
- React/Vite вызывает MVC Web через `/api` reverse proxy; успешные ответы модулей имеют существующие разные обёртки.
- `Web/Program.cs` — composition root. Data содержит application services и Kafka producer. Расчёты выполняют три ASP.NET gRPC-сервиса и Python FurnaceService.
- Aglom и Slag дополнительно требуют внешние REST-сервисы на 5296/44324. GasDynamic и Furnace считают локально.
- EF Core/Npgsql, отдельные контексты/БД модулей, миграции в Core. AuthDBContext содержит пользователей Identity с int ID.
- История Aglom/Slag хранится как EF-граф, GasDynamic/Furnace — JSON. Web публикует в Kafka синхронно, CalculationHistoryWriter сохраняет историю асинхронно.
- Имеющиеся пресеты — стартовые записи/IsPreset без пользовательского имени и описания. Frontend отдельно хранит краткую историю в localStorage.
- Выявлена заглушка в AglomModeController.Calculate: библиотека не вызывается. Её необходимо убрать при подключении общего pipeline.
- API возвращает произвольные сообщения ошибок и маскирует инфраструктурные ошибки как 400. Startup перехватывает исключения и не сообщает о неудачном запуске.
- Общие gRPC сообщения содержат только JSON (поле 1). Номера сохраняются, метаданные добавляются новыми полями.
- Общих comparison, transition mapper, report exporter, health checks и Outbox нет.

## Минимальное расширение

Переиспользовать существующие проекты, DI, Newtonsoft, Identity и EF Core. Общие пользовательские пресеты, журнал JSON и Outbox разместить в существующей AuthDB (AuthDBContext), без нового микросервиса или базы. Это позволяет атомарно сохранить расчёт и событие одной транзакцией. Старые таблицы модулей и endpoints сохраняются; worker продолжает их заполнять и обновляет общий статус после успешного сохранения. Общий журнал используется новыми экранами истории, сравнения и экспорта.

Порядок: ошибки API → валидация и gRPC → история/Outbox → пресеты → сравнение → Aglom→Slag → экспорт → health → frontend → проверка/документация. По одному коммиту на завершённый этап.

## Исходная проверка

- `dotnet restore/build`: успешно; имеются существующие nullable warnings и предупреждение NuGet об AutoMapper 15.0.1.
- `dotnet test`: 1/4 успешно, 3 теста Aglom/Slag зависят от недоступных внешних REST-сервисов. Это не считается успешной полной проверкой.
- Docker daemon при первом обращении недоступен. Проверку контейнеров требуется выполнить отдельно.
- Формулы Furnace по указанию пользователя сохранены как исходные; методика/исходный Excel отсутствуют.
