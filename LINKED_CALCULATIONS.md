# Связанные расчёты

Связи определены по фактическим входным/выходным моделям и единицам. Это доступные переходы между модулями, а не обязательная линейная последовательность всех расчётов.

| Источник → следующий модуль | Перенос |
| --- | --- |
| Aglom → Slag | Итоговый состав агломерата: Fe, S, CaO, SiO₂, Al₂O₃, MgO, MnO, TiO₂ → компонент Agglomerate23. Расход компонента сохраняется. |
| Slag → тепловой баланс | SlagOut → slag_rate (кг/т чугуна), SContentInCastIron → S (%), CastIronTemp → T_iron (°C). |
| Газодинамический режим → тепловой баланс | Udeln_Koks_1000 → coke_rate (т/т × 1000 → кг/т); Kolgaz_CO2/CO/H2/N2 → top_CO2/CO/H2/N2 (доля × 100 → %). |

Остальные вводы берутся из последнего черновика целевого модуля, а при первом открытии — из его исходного набора. Переход очищает предыдущий результат целевого модуля. Следующий расчёт пользователь запускает отдельно; сервер проверяет владение исходным расчётом и сохраняет sourceCalculationId в истории нового результата. Связь сохраняется и после открытия целевой страницы без URL-параметров.

Не переносим общий расход материалов Slag в ore_rate: определения величин не совпадают достаточно однозначно. Не переносим теоретическую температуру горения в температуру дутья. Метан колошникового газа не имеет отдельного поля в Furnace; остальные доли не нормализуются искусственно. У теплового баланса результаты обозначены Cxx без подтверждённого соответствия другим входам. Массовый баланс и восстановительные процессы пока не выполняют расчёты в текущем frontend; переходы с них не заявлены.

Точки проверки: BaseLib/SlagMode/Models/ResponseData.cs, единицы в SlagModeResults.tsx, BaseLib/BlastFurnaceSmeltingGasDynamicMode/BlastFurnaceSmeltingGasDynamicModeXLLibrary.cs (расход кокса 1e-3 и расчёт долей газа), FurnaceService/app/models.py и tests/sample.json.

Для справки при исследовании порядка этапов найдены учебные программы [УрФУ: проектный практикум по технологии доменного процесса](https://nti.urfu.ru/data/pages/27/125_ProektnyypraktikumTehnologiyadomennogoprocessa-A_2023.pdf) и [современные процессы чёрной металлургии](https://nti.urfu.ru/data/pages/27/M15_sovr_processy_ChM_2023.pdf). Поисковые выдержки рассматривают шлаковый, материальный и тепловой балансы и колошниковый газ; сами PDF при открытии были недоступны. Нумерация тем учебной программы не использована как доказательство обязательного порядка вычислений. Соответствия полей подтверждены кодом проекта.

## Как проверить на стенде

1. Открыть «Сохранённые расчёты», выбрать «Агломерационная шихта» и нажать «Открыть расчёт» у демонстрационной записи. На вкладке «Результаты» нажать «Шлаковый режим» в блоке «Перенести результаты далее». Проверить Fe=58.124, CaO=8.468 и сохранённый расход компонента. Закрытый API для самого переноса не нужен.
2. В газодинамическом режиме нажать «Рассчитать». На вкладке результатов нажать «Тепловой баланс». Проверить расход кокса и проценты газа, затем запустить расчёт теплового баланса.
3. Для Slag → тепловой баланс нужен результат Slag от закрытого API команды или ранее сохранённый результат этого модуля. Mapper отдельно проверен локальными тестами.
4. Изменить ввод, перейти в другой модуль и вернуться; затем обновить страницу. Вводы, последний результат и вкладка должны восстановиться. Явный переход из другого расчёта имеет приоритет над старым результатом целевой формы.

Автосохранение работает в localStorage отдельно для пользователя и модуля. Очистка данных сайта удаляет локальные черновики. Серверная история и именованные шаблоны сохраняются независимо.
